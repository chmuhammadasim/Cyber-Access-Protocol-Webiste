The disciplines

What the operation asks you to know.

Every discipline has its own mission, threats and field doctrine. The first nine belong to The Last Signal; the frontier adds nine more; the living system adds the ten operational domains that tie the campaign together.

DISCIPLINE 01 // INTELLIGENCE

Threat Intelligence

Intelligence work turns raw, untrusted reporting into a defensible assessment. Every claim keeps its source, its confidence and its date, and duplicates collapse into one record. A judgement without provenance is a guess wearing a uniform.

DISCIPLINE 02 // HUNTING

Threat Hunting

A hunt starts from a hypothesis, not an alert. Search the local telemetry for the behaviour you expect, then prove or disprove it. Record negative results as well — the absence of a signal is evidence too.

DISCIPLINE 03 // FORENSICS

Forensic Analysis

Forensics preserves the artifact before interpreting it. Capture the hash, the timestamp and the chain of custody first; only then reconstruct the timeline. An untracked copy is not evidence.

DISCIPLINE 04 // PURPLE TEAM

Purple Team

Purple teaming pairs the defender who sees the telemetry with the attacker who knows the path. The result is not a winner but a measured control: what was detected, what was missed, and what changes next.

DISCIPLINE 05 // VULNERABILITY

Vulnerability Management

A finding is not a priority. Rank by reachable exposure, business impact and the time an adversary needs. The zero-day clock rewards a scoped patch over an untested emergency change.

DISCIPLINE 06 // RESILIENCE

Resilience Engineering

Resilience is measured by recovery, not by prevention alone. Know your RPO and RTO, rehearse the restore, and record what the exercise actually proved.

DISCIPLINE 07 // AI GOVERNANCE

AI Governance

A model earns trust with evidence: evaluation results, bounded data, human review and a named owner. Capability is not authorization, and a confident output is not a validated one.

DISCIPLINE 08 // INSIDER RISK

Insider Risk

Insider risk is a behaviour and access problem, not a loyalty test. Least privilege, separation of duties and auditable exceptions protect the person and the organisation.

DISCIPLINE 09 // INCIDENT COMMAND

Incident Command

An incident is coordinated under one commander with one common operating picture. Declare scope, assign owners, preserve evidence and record decisions while the clock runs.

DISCIPLINE 10 // EDGE

Edge and Device Lifecycle

An edge device is only trusted when it has an owner, a purpose, verified firmware and a policy it actually enforces. Inventory is a living record, not a spreadsheet.

DISCIPLINE 11 // OT

OT and Process Safety

Industrial security has to protect the process without stopping the plant. Safety, availability and security constraints are negotiated together.

DISCIPLINE 12 // COMMUNICATIONS

Communications Resilience

No single point of failure, no silent fallback. Prove the alternate path works before the primary path disappears.

DISCIPLINE 13 // REMOTE

Remote Continuity

An outage is a test of what stayed available. Remote teams need a documented mode, not an improvised one.

DISCIPLINE 14 // PRIVACY

Privacy Engineering

Collect the minimum the service needs. Every retained field has to earn its place against purpose, retention and recipient.

DISCIPLINE 15 // SOVEREIGNTY

Data Sovereignty

Cross-organisation data needs named authority, bounded scope and an approval trail that survives the handoff.

DISCIPLINE 16 // ARCHITECTURE

Security Architecture

A diagram is a claim. Validate the architecture against the scenario: trust boundaries, dependencies and failure modes included.

DISCIPLINE 17 // CRISIS

Crisis Communication

Verify before publishing. One approved status beats a fast rumour, especially when the crowd is already broadcasting.

DISCIPLINE 18 // FEDERATED

Federated Incident Command

Coordinate a shared incident without bypassing local authority. One picture, many owners, explicit decision rights.

Chapter VII // The Living System

Ten operational domains. One configuration surface.

Every V7 mission gives you a system to repair and a requirement set to prove. The domain names below are the mission's own vocabulary.

Levels 61–70
GUI + terminal
DOMAIN 19 // ENDPOINT

Endpoint Operations

Baseline every workstation: accountable owner, stated purpose, approved state and active monitoring. Drift is a record problem before it is an attack.

DOMAIN 20 // NETWORK

Network Engineering

Rebuild the topology and validate every path. The canvas and the command tab edit the same links; the path checker does not care which one you used.

DOMAIN 21 // IDENTITY

Identity Administration

A consistent lifecycle and least privilege across users, service identities and roles. No identity keeps administrator by habit.

DOMAIN 22 // CLOUD

Cloud Security

Guardrails that hold for every resource: no public exposure, encryption on, logging on, ownership and retention explicit.

DOMAIN 23 // PIPELINE

Secure Delivery

A build line is trustworthy when its gates block. Prove the test and artifact stages are real gates, not decorations.

DOMAIN 24 // DETECTION

Security Monitoring

Turn noisy telemetry into validated detection coverage: active sources, enabled rules, real thresholds and a stated condition for each rule.

DOMAIN 25 // INCIDENT

Incident Command

Repair the playbook, order the response and run the incident. Approved actions, safe sequence and preserved evidence are the mission.

DOMAIN 26 // RECOVERY

Recovery Operations

Restore critical services in dependency order, with verified backups, honest RTOs and an isolated copy that survives the next incident.

DOMAIN 27 // AI GOVERNANCE

AI Governance

Bound the model: named owner, stated purpose, scoped tools, human approval and a state you can verify. Capability is not authorization.

DOMAIN 28 // ASSURANCE

Operations Assurance

The integrated final: every domain, one approved baseline, one audit trail and a deliberate choice about how much automation survives.

The adversary

The Conductor

A patient adversary who attacks the record itself: logs, ownership, evidence and trust. The campaign is won by the record you kept, the teams you coordinated and the limits you refused to remove — not by out-hacking a villain.

The Null Architect is the presence behind the tower incident. The Conductor is the force behind the AEGIS drift: both are framed through defense, recovery and the people inside the building, never as a power fantasy.

Chapter VII // Configuration

The workbench is the mission.

A record list, a draft, a requirement set and a command tab. Change a field and the requirements update; change a link on the canvas and the same record moves; run an order change in the timeline and the draft remembers. Apply only when validation passes.

One draft
GUI · terminal · canvas · timeline
Command tab

The same work, a different surface

The fictional command grammar is allowlisted and local. It edits the same draft as the GUI, so a link created with link is visible in the canvas and validated by the same engine. Nothing here touches a real shell, network or service.

Certification

A proof, not a participation badge

Levels 11–60 require six practical tasks from a mission-specific scenario; Levels 1–10 use a six-step station; Levels 61–70 validate the full mission scenario. The certified result is stored with the save and unlocks the exit.

Cross-mission consequences

The next mission remembers the last one.

Your choices and the evidence you keep carry into the next operation. A clean mission changes how the team speaks to you; a strong record can unlock new evidence to find. The character sheet, dialogue history, certifications and case files all survive between levels.

A strong operation can add a cross-reference clue and a decision that asks you to use the archive you built. From Chapter VII the practical chain also carries forward: the configuration you certified changes what the next room trusts.

Current scope, stated plainly

Your first playthrough is your story. Replays are yours to experiment with and never overwrite the consequences you have already earned.

Two finals

Six ways for the signal to end.

Level 50 ends the tower with a command-lock choice. Level 70 ends the living system with an operating-model choice. Both are saved with the campaign.

A / B / C twice
Yours to choose
Level 50 // The Last Signal
A

Coordinated Defense

The network holds because every team answers at once. Your evidence archive becomes the first shared record of the Null Architect's campaign. The operators you trusted rest, and the signal goes quiet — watched, not silenced.

B

Controlled Automation

The response runs itself: fast, tireless, and blind to what it was never taught. The last signal fades behind an automated watch. You keep the logs, and wonder what the system will decide next.

C

Full Shutdown

Every relay goes dark. The Null Architect cannot reach the network because there is no network left to reach. The silence is safe. It is also yours to rebuild.

Level 70 // The Living System
A

Centralized Emergency Control

Centralized control restored the campus quickly, at the cost of deeper central dependence. It is the fastest answer and the one that concentrates the next failure.

B

Manual Operations

Manual operations preserved direct human control, but every response now takes longer. The campus is safe, awake and slower than the adversary.

C

Governed Automation

Approved baseline, bounded authority, human approval, monitoring, rollback and a complete audit trail. The campus keeps its speed without giving up the record.

Common questions

The living system, answered.

Spoiler-light
Story first

What is this field manual?

The complete reference for Cyber Access Protocol: seven chapters, twenty-eight specialist disciplines, the V7 configuration workbench and the campaign's two finals.

How many missions does the campaign have?

Seventy levels in total: ten continuous tower levels and sixty standalone missions from Level 11 to Level 70. Each mission has its own rooms, evidence, decisions and boss.

Do my choices carry between missions?

Yes. Evidence, character equipment, dialogue history, case files and certification follow you into the next operation; the practical chain changes what the next room trusts.

How many endings are there?

Six, across two finals. Level 50 chooses Coordinated Defense, Controlled Automation or Full Shutdown; Level 70 chooses Centralized Emergency Control, Manual Operations or Governed Automation.
